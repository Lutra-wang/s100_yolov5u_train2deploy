# 问题说明

## P-01：COCO 下载 HTTPS 主机名不匹配

- 现象：当前 WSL 网络对 `images.cocodataset.org` 的 HTTPS 证书主机名校验失败。
- 处理：使用同一官方 COCO 下载端点的 HTTP 地址下载 `val2017.zip` 与 `annotations_trainval2017.zip`，没有关闭 TLS 校验或使用第三方镜像。
- 预防：在正常网络优先使用手册的 HTTPS URL；发生同类网络设备证书替换时，检查网络后才按环境策略处理。

## P-02：官方 BPU COCO 模式仅接受 5,000 张图

- 现象：`py/rdk_yolo_app.py --mode coco2017` 对非 5,000 张输入直接退出。
- 根因：该模式是官网 COCO2017 完整验证集的保护性入口，不是自定义子集批处理入口。
- 处理：新增 `run_model_zoo_bpu_subset.py`，只循环调用官方 `Ultralytics_YOLO_Detect` 并原样保存 `info`；没有复制或修改官方预处理、BPU 调用、DFL 解码或 NMS。`evaluate_coco_official.py` 仅做结果格式桥接并调用原始 pycocotools。

## P-03：板端缺少 tqdm

- 现象：第一次直接导入官方检测类时报告 `ModuleNotFoundError: tqdm`。
- 根因：直接类导入绕过了官方 `rdk_yolo_app.py` 中的依赖自检。
- 处理：适配器先导入官方入口，触发其原有的依赖安装逻辑；板端自动安装了 `tqdm 4.70.1`，第二次 16 图 BPU Python 推理成功。

## P-04：SSH 主机密钥变化

- 现象：`192.168.127.10` 的记录密钥与当前 ED25519 指纹不符。
- 处理：在用户确认 `SHA256:IDmdMLvf3cET0+X+qbsJpAIxo4XtibiULpnohvFp7/I` 后，备份本机 known_hosts、移除该 IP 的旧条目并重新信任新指纹；随后以用户提供的 root 密码完成部署。
- 预防：不得用 `StrictHostKeyChecking=no` 绕过该告警；每次板卡重刷或地址复用都先人工核对指纹。
