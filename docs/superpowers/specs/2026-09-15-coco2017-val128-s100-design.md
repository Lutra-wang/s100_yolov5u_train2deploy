# COCO 2017 Val128 S100 重建设计

## 目标

在 `/home/lutra/OE_S100` 保持既有目录结构，使用 Horizon OE 与 `model_zoo_s` 的官方 YOLOv5u 样例，从官方预训练初始权重重新训练一个与官网 COCO128 不同的 128 图像数据集，并完成转换、S100 部署、精度和延迟评估。

## 数据集

数据集名为 `coco2017_val128_s100`。其来源为 COCO 2017 `val2017`，通过工程内固定清单选择 128 张图像；官网 COCO128 来自 `train2017`，两个源集合不相交。训练、验证、测试固定划分为 96 / 16 / 16。公开下载地址、固定图像 ID、标注筛选规则和生成命令均写入操作手册，因此新环境无需复制旧数据或旧产物。

## 工具链边界

训练与 ONNX 导出使用官方 Ultralytics 发行版；量化、编译和板端 Python 推理使用 `model_zoo_s/samples/Vision/ultralytics_yolo` 的官方脚本。先检索 OE/Model Zoo 是否已有数据和评估脚本；只有缺少“定制 128 集合构造”或“官方 BPU Python txt 输出到 COCOeval”的连接能力时，才提供最小辅助脚本，并在手册说明该脚本不参与模型推理、后处理或编译。

## 可追溯性与迁移

现有 COCO128 相关数据、训练权重、ONNX、校准、HBM、板端结果、评估记录和旧文档复制到 `/home/lutra/OE_S100_archive_coco128_previous` 后，通过清单和 SHA-256 校验，再从工作目录删除对应文件。`model_zoo_s` 源码、通用环境说明与非数据集产物不删除。

## 评估

精度使用 COCOeval 的官方 `bbox` 指标，输出 FP32 与 S100 BPU Python 的 `mAP@[.50:.95]`，并按 all/small/medium/large 面积分组。两者使用同一测试集、类别映射、NMS、置信度阈值和 COCOeval 配置。延迟使用 S100 的官方 Model Zoo 性能程序并保存完整命令和原始日志。

## 验收

必须存在新训练 `best.pt`、ONNX、HBM、S100 BPU Python 原始结果、FP32/BPU COCO JSON、精度报告、延迟报告和可从零执行的操作手册；报告中的指标只能引用本轮生成的原始日志与结果文件。
