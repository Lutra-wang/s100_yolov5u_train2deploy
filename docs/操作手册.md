# RDK S100：YOLOv5nu 从训练到部署操作手册

## 1. 目标与交付物

本手册从零复现一条 YOLOv5nu 目标检测链路：构建一套不同于官网 COCO128 的 128 图数据集，训练、使用官方 Model Zoo 和 OpenExplorer（OE）量化编译、部署到 S100，并生成精度和 BPU 时延评估。

最终交付：

- `train/runs/.../weights/best.pt`：训练权重；
- `exchange/onnx/*.onnx`：官方 Model Zoo 导出的 ONNX；
- `conversion/output/*.hbm`：S100 `nash-e` HBM；
- `validation/quantization_{fp32,bpu}_metrics.json`：量化前后精度；
- `board/output/perf_{1thread,2thread}.log`：板端时延；
- `docs/精度评估.md`、`docs/延迟评估.md`：评估结果整理。

训练、导出和评估在开发机执行；OE 编译在官方 Docker 容器执行；推理和时延测试在 S100 执行。将 `<S100_HOST>` 替换为板卡地址。

## 2. 获取组件和创建工程

开发机需要 Git、Conda、Docker，以及从 D-Robotics 官方渠道获得的 OpenExplorer 3.7.0。板端需要可运行的 RDK S100 系统和 SSH 登录权限。

在开发机执行：

```bash
export ROOT="$HOME/OE_S100"
export OE_DIR="/opt/drobotics_s100_s600_open_explorer_v3.7.0"
mkdir -p "$ROOT"/{data/_sources/coco2017,train,exchange/onnx,conversion,validation,board/output,docs,scripts}

git clone --branch s100 --single-branch https://github.com/D-Robotics/rdk_model_zoo_s.git "$ROOT/model_zoo_s"
git clone --branch v8.4.152 --single-branch https://github.com/ultralytics/ultralytics.git "$ROOT/train/ultralytics"
ln -s "$OE_DIR" "$ROOT/oe"

conda create -y -n oe-s100-yolov5u python=3.10 pip
conda run -n oe-s100-yolov5u python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
conda run -n oe-s100-yolov5u python -m pip install -e "$ROOT/train/ultralytics" pycocotools
```

检查：`test -x "$ROOT/oe/run_docker.sh"` 通过，且 `conda run -n oe-s100-yolov5u yolo version` 能输出版本。

本案例包含三个必要的轻量辅助脚本，随手册交付并放入 `$ROOT/scripts/`：

- `build_coco2017_val128_s100.py`：从 COCO `val2017` 固定选 128 图并生成 YOLO 标签；
- `evaluate_coco_official.py`：转换预测为 COCO JSON，调用未修改的 `pycocotools`；
- `run_model_zoo_bpu_subset.py`：对固定 16 图重复调用官方 `Ultralytics_YOLO_Detect`。

官方没有“自定义 128 图选集”和“16 图 COCO 模式”命令，因此仅在这些位置使用辅助脚本；模型导出、量化编译、BPU 推理、解码与 NMS 均使用官方工具或官方 Model Zoo 类。确认脚本已就位：

```bash
test -f "$ROOT/scripts/build_coco2017_val128_s100.py"
test -f "$ROOT/scripts/evaluate_coco_official.py"
test -f "$ROOT/scripts/run_model_zoo_bpu_subset.py"
```

## 3. 构建固定 128 图数据集

在开发机执行。官网 COCO128 从 `train2017` 选图；本案例从 `val2017` 按 image id 升序取前 128 张，因此源集合不重合。数据划分固定为 train/val/test = 96/16/16。

```bash
cd "$ROOT/data/_sources/coco2017"
wget -c https://images.cocodataset.org/zips/val2017.zip
wget -c https://images.cocodataset.org/annotations/annotations_trainval2017.zip
unzip -n val2017.zip
unzip -n annotations_trainval2017.zip annotations/instances_val2017.json

conda run -n oe-s100-yolov5u python "$ROOT/scripts/build_coco2017_val128_s100.py" \
  --annotations "$ROOT/data/_sources/coco2017/annotations/instances_val2017.json" \
  --images-dir "$ROOT/data/_sources/coco2017/val2017" \
  --output "$ROOT/data/coco2017_val128_s100"
conda run -n oe-s100-yolov5u python "$ROOT/scripts/build_coco2017_val128_s100.py" \
  --output "$ROOT/data/coco2017_val128_s100" --verify
```

检查：输出应为 `{"test": 16, "train": 96, "val": 16}`；`dataset.yaml`、`selection.json` 和 `annotations/instances_test.json` 均存在。

## 4. 从官方初始权重训练

在开发机执行。`yolov5nu.pt` 是 Ultralytics 官方 COCO 预训练初始权重；本次训练的 `best.pt` 才是用于后续导出和编译的模型。

```bash
mkdir -p "$ROOT/train/initial"
cd "$ROOT/train/initial"
conda run -n oe-s100-yolov5u yolo detect train \
  model=yolov5nu.pt data="$ROOT/data/coco2017_val128_s100/dataset.yaml" \
  imgsz=640 epochs=10 batch=8 workers=0 device=cpu \
  project="$ROOT/train/runs" name=coco2017_val128_s100 \
  seed=20260915 deterministic=True

RUN="$(find "$ROOT/train/runs" -mindepth 1 -maxdepth 1 -type d -name 'coco2017_val128_s100*' | sort | tail -1)"
test -s "$RUN/weights/best.pt"
test -s "$RUN/results.csv"
printf 'RUN=%s\n' "$RUN"
```

检查：记录输出的 `RUN` 路径。重复运行时该目录可带数字后缀，后续命令始终使用实际的 `RUN`。

## 5. 使用官方 Model Zoo 导出 ONNX

在开发机执行。使用 Model Zoo 的 `export_monkey_patch.py`，以导出与其 S100 部署代码匹配的 YOLOv5u 六路分类/DFL 输出。

```bash
mkdir -p "$ROOT/exchange/onnx"
conda run -n oe-s100-yolov5u python \
  "$ROOT/model_zoo_s/samples/Vision/ultralytics_yolo/x86/export_monkey_patch.py" \
  --pt "$RUN/weights/best.pt" --optse 11
cp "$RUN/weights/best.onnx" "$ROOT/exchange/onnx/yolov5nu_coco2017_val128_s100.onnx"
conda run -n oe-s100-yolov5u python -c "import onnx; onnx.checker.check_model('$ROOT/exchange/onnx/yolov5nu_coco2017_val128_s100.onnx'); print('onnx-ok')"
```

检查：输出 `onnx-ok`；模型包含 `output0`、`371`、`379`、`387`、`395`、`403` 六个输出。

## 6. 准备校准图并使用 OE 编译

在开发机执行。校准集为训练集中按文件名排序的前 20 张图片；使用官方 Model Zoo `mapper.py` 和 OE 3.7.0 Docker 镜像编译。

```bash
mkdir -p "$ROOT/conversion/cal_images" "$ROOT/conversion/output"
find "$ROOT/data/coco2017_val128_s100/images/train" -maxdepth 1 -name '*.jpg' | sort | head -20 \
  | xargs -r -I{} cp '{}' "$ROOT/conversion/cal_images/"
test "$(find "$ROOT/conversion/cal_images" -maxdepth 1 -name '*.jpg' | wc -l)" -eq 20

docker run --rm --network host --user "$(id -u):$(id -g)" \
  -v "$ROOT/oe":/open_explorer -v "$ROOT":/data \
  registry.d-robotics.cc/deliver/ai_toolchain_ubuntu_22_s100_s600_cpu:v3.7.0 \
  bash -lc 'cd /data/conversion && python3 /data/model_zoo_s/samples/Vision/ultralytics_yolo/x86/mapper.py \
    --onnx /data/exchange/onnx/yolov5nu_coco2017_val128_s100.onnx \
    --cal-images /data/conversion/cal_images --output-dir /data/conversion/output \
    --march nash-e --jobs 16 --optimize-level O2 --save-cache True' \
  | tee "$ROOT/conversion/mapper.log"
```

检查：存在 `conversion/output/yolov5nu_coco2017_val128_s100_nashe_640x640_nv12.hbm` 和 `hb_compile.log`，且日志含 `The hb_compile completes running.`。日志中的 six-output calibrated/quantized cosine 用于量化诊断。

## 7. 上板、单图推理和测试集推理

先在开发机传输，再在 S100 推理。板端目录固定为 `/root/OE_S100_coco2017_val128_s100`。

```bash
export S100_HOST="root@<S100_HOST>"
export BOARD_ROOT="/root/OE_S100_coco2017_val128_s100"
ssh "$S100_HOST" "mkdir -p $BOARD_ROOT/output"
scp -r "$ROOT/model_zoo_s/samples/Vision/ultralytics_yolo/py" "$S100_HOST:$BOARD_ROOT/"
scp "$ROOT/scripts/run_model_zoo_bpu_subset.py" "$S100_HOST:$BOARD_ROOT/"
scp "$ROOT/conversion/output/yolov5nu_coco2017_val128_s100_nashe_640x640_nv12.hbm" "$S100_HOST:$BOARD_ROOT/"
scp -r "$ROOT/data/coco2017_val128_s100/images/test" "$S100_HOST:$BOARD_ROOT/"
```

在 S100 执行单图可视化（图片文件名改为 `test/` 中的实际文件）：

```bash
cd /root/OE_S100_coco2017_val128_s100
python3 -m py.rdk_yolo_app \
  --model-path ./yolov5nu_coco2017_val128_s100_nashe_640x640_nv12.hbm \
  --source ./test/000000000632.jpg --workspace ./output/single_image \
  --mode default --yolo-type yolov5u --model-type detect \
  --score-thres 0.25 --nms-thres 0.7
```

检查：`output/single_image/` 中出现 `_result.jpg` 可视化图片。

在 S100 对 16 张测试图生成 BPU 原始结果：

```bash
cd /root/OE_S100_coco2017_val128_s100
python3 ./run_model_zoo_bpu_subset.py \
  --model-zoo-yolo-dir ./py \
  --model-path ./yolov5nu_coco2017_val128_s100_nashe_640x640_nv12.hbm \
  --source ./test --output ./output/bpu_result.txt \
  --score-thres 0.25 --nms-thres 0.7
```

检查：末尾输出 `images=16`；`bpu_result.txt` 每行具有八列：`image_id detection_id class_id score x1 y1 x2 y2`。在开发机拉回结果：

```bash
scp "$S100_HOST:$BOARD_ROOT/output/bpu_result.txt" "$ROOT/board/output/bpu_result.txt"
```

## 8. 测量板端 BPU 时延

在 S100 执行。该数据是 BPU 模型任务基准，不含图片读写、预处理和后处理。

```bash
cd /root/OE_S100_coco2017_val128_s100
hrt_model_exec model_info --model_file ./yolov5nu_coco2017_val128_s100_nashe_640x640_nv12.hbm | tee ./output/model_info.log
hrt_model_exec perf --thread_num 1 --model_file ./yolov5nu_coco2017_val128_s100_nashe_640x640_nv12.hbm | tee ./output/perf_1thread.log
hrt_model_exec perf --thread_num 2 --model_file ./yolov5nu_coco2017_val128_s100_nashe_640x640_nv12.hbm | tee ./output/perf_2thread.log
```

在开发机拉回并检查：

```bash
scp "$S100_HOST:$BOARD_ROOT/output/perf_1thread.log" "$ROOT/board/output/"
scp "$S100_HOST:$BOARD_ROOT/output/perf_2thread.log" "$ROOT/board/output/"
grep -E 'Thread Average|FPS' "$ROOT/board/output/perf_"*thread.log
```

将两个日志的 `Thread Average` 和 `FPS` 写入 `docs/延迟评估.md`，保留原始日志。

## 9. 生成量化前后精度文件

在开发机执行。FP32 与 BPU 使用同一套 16 张 test 图、640×640、score threshold 0.25、NMS IoU 0.7。评估脚本只负责格式转换与 `pycocotools` 计算；BPU 的预处理、推理、解码、NMS 均为官方 Model Zoo 实现。

```bash
ANN="$ROOT/data/coco2017_val128_s100/annotations/instances_test.json"
conda run -n oe-s100-yolov5u python "$ROOT/scripts/evaluate_coco_official.py" fp32-to-json \
  --weights "$RUN/weights/best.pt" --images-dir "$ROOT/data/coco2017_val128_s100/images/test" \
  --annotations "$ANN" --output "$ROOT/validation/quantization_fp32_predictions.json" \
  --imgsz 640 --conf 0.25 --iou 0.7
conda run -n oe-s100-yolov5u python "$ROOT/scripts/evaluate_coco_official.py" bpu-to-json \
  --bpu-text "$ROOT/board/output/bpu_result.txt" --annotations "$ANN" \
  --output "$ROOT/validation/quantization_bpu_predictions.json"
for kind in fp32 bpu; do
  conda run -n oe-s100-yolov5u python "$ROOT/scripts/evaluate_coco_official.py" evaluate \
    --annotations "$ANN" --predictions "$ROOT/validation/quantization_${kind}_predictions.json" \
    --metrics "$ROOT/validation/quantization_${kind}_metrics.json"
done
```

检查：两个 metrics JSON 包含 `map50`、`map50_90`、`bbox_all_map_50_95`、`image_count`、`detection_count`。把这三项 mAP 及 `hb_compile.log` 中的 six-output cosine 写入 `docs/精度评估.md`。16 图结果用于链路回归和量化前后观察，不替代官网 COCO2017 5,000 图发布基准。
